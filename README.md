# 🌿 Ansh AI — मराठी AI Chatbot SaaS

Ansh AI is a production-ready, **Marathi-first** AI chatbot SaaS built in **pure PHP 8.2+ and MySQL 8+** — no frameworks, no Composer, no Node. It runs on ordinary shared/VPS PHP hosting. a full role-based admin panel where the whole business is configurable without touching code.

---

## 1. Technology Stack

| Layer | Technology |
|-------|------------|
| Backend | PHP 8.2+ (`declare(strict_types=1)`), PDO |
| Database | MySQL 8+ (utf8mb4 for Devanagari) |
| Frontend | HTML5, CSS3, vanilla JS, Tailwind (CDN), Lucide icons |
| AI | Google Gemini via server-side cURL (`v1beta/generateContent`) |
| Payments | PayU (hosted checkout, SHA-512 request/response hashing) |
| Email | Native SMTP over `stream_socket_client` (STARTTLS/SSL/plain, AUTH LOGIN) |
| Admin charts | Chart.js (CDN) |

**Not used (by design):** Node.js, npm/yarn, React/Vue/Angular, Laravel/Symfony/CodeIgniter, Composer, Vite/Webpack, Bootstrap. The app is deployable by uploading files and importing one `.sql` file.

## 3. Setup / Installation

### Requirements
- PHP **8.2+** with extensions: `pdo_mysql`, `openssl`, `curl`, `mbstring`
- MySQL **8+** (or MariaDB 10.4+)
- Apache with `mod_rewrite` + `mod_headers` (or nginx equivalent), HTTPS

### Option A — Guided installer (recommended)
1. Upload all files to your web root.
2. Create an empty MySQL database (e.g. `ansh_ai`) and a DB user.
3. Ensure `config/` is writable by PHP during install.
4. Visit `https://your-domain.com/admin/install.php`.
5. Fill in App URL, DB credentials, and the **first super-admin** account (you choose the password — nothing is hard-coded).
6. The installer runs the schema, generates a 64-char `APP_KEY`, writes `config/config.php` with `INSTALLED=true`, creates the super-admin, and **locks itself**.
7. **Delete or block `admin/install.php`**, then log in at `/admin/login.php`.

### Option B — Manual
1. Import the schema: `mysql -u USER -p ansh_ai < database.sql`
2. `cp config/config.example.php config/config.php`
3. Fill DB creds; generate a key: `php -r "echo bin2hex(random_bytes(32));"` → `APP_KEY`
4. Set `'INSTALLED' => true`.
5. Create a super-admin (via installer, or insert into `admin_users` with a `password_hash()` value).
6. Configure Gemini / PayU / SMTP in the admin panel.

### Cron jobs
Add to crontab (adjust the PHP path):
```
0 1 * * *  php /path/to/cron/expire_subscriptions.php
0 9 * * *  php /path/to/cron/send_expiry_reminders.php
30 1 * * * php /path/to/cron/cleanup_tokens.php
0 2 * * *  php /path/to/cron/cleanup_logs.php
```
Web-triggered cron (if no CLI): set a `cron_secret` setting and call `?token=SECRET`.

## 6. Configuration Procedures (Admin Panel)

**PayU** → Admin → Payment Settings: enter Merchant Key + Salt (encrypted), choose `test`/`production`. Prices are editable (`price_monthly`, `price_yearly`). The server builds the SHA-512 request hash and **verifies the SHA-512 response hash** before granting premium — frontend success is never trusted.

**SMTP** → Admin → SMTP Settings: host, port, encryption (tls/ssl/none), username/password (encrypted), from name/email. Use **Test SMTP** to send a probe email. Templates are edited under Email Templates with `{{variable}}` placeholders.

## 7. Security Checklist

- [x] `declare(strict_types=1)` everywhere; PDO **prepared statements only**
- [x] Gemini/PayU/SMTP secrets **encrypted at rest** (AES-256-GCM, keyed by `APP_KEY`); never rendered to frontend
- [x] Gemini key server-side only — no key in HTML/JS
- [x] PayU response hash **verified server-side** before premium is granted
- [x] Passwords hashed with `password_hash()`; tokens stored as SHA-256 hashes
- [x] CSRF synchronizer tokens on all state-changing requests
- [x] Rate limiting on login, registration, password reset, AI, payments
- [x] Role-based admin permissions; audit log with **secret redaction**
- [x] `.htaccess` blocks `config/`, `includes/`, `storage/`, `cron/`, dotfiles, `*.sql/.log/.md`
- [x] Uploads directory **cannot execute PHP**
- [x] Security headers: HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy
- [x] Production hides PHP errors/stack traces; details go to `storage/logs`
- [x] Installer **self-locks** after setup; no hard-coded admin password
- [x] Chat content never shown in admin (privacy by design)

> **Deploy note:** the app itself does not enforce TLS at the PHP layer beyond the `.htaccess` redirect — confirm HTTPS is active and valid before going live, and keep `APP_ENV=production`.
